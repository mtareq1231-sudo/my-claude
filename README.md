# رسالة الترحيب التلقائية

بوت بيرد تلقائياً على العميل **بعد دقيقة** من أول رسالة يبعتها، برسالة ترحيب فيها
تأكيد استلام ولينك الموقع ورقم التواصل — على **واتساب وماسنجر وانستجرام** من سيرفر واحد.

- ✅ التأخير دقيقة (قابل للتعديل)
- ✅ كل عميل بيستلم الرسالة **مرة واحدة بس** — مش كل ما يبعت
- ✅ الرسايل المجدولة بتفضل موجودة حتى لو السيرفر وقف واشتغل تاني
- ✅ بيتجاهل إشعارات التسليم والقراءة وردودنا الراجعة (echo)

## ليه كود ومش الأدوات الجاهزة؟

رسالة الترحيب في تطبيق واتساب بيزنس وأتمتة Meta Business Suite بترد **فوراً** وبس —
مفيش فيها خيار "استنى دقيقة"، ولا "مرة واحدة لكل عميل". عشان كده الجزء ده لازمه سيرفر.

## التشغيل

### 1. المحتوى

محتوى الرسالة كله في [`config/business.json`](config/business.json)، والملف متعبّى
بالفعل ببيانات Warmup المسحوبة من المتجر:

```
أهلاً بك في Warmup
تم استلام رسالتك، وسنرد عليك في أقرب وقت.

تسوّق الآن على موقعنا:
https://warmupjo.com

للاستفسار: +962 79 222 5298
```

الرسالة بتطمّن العميل الأول إن رسالته وصلت، بعدين بتوجّهه يتسوّق من **الموقع**.
صيغة سطر الدعوة نفسها في حقل `websiteCta` لو حبيت تغيّرها. اللينك واخد سطر لوحده عشان يبقى أسهل في الضغط وعشان الشات يعرض له معاينة
(link preview)، والتليفون سطر تاني قصير كبديل مش كدعوة.
عشان كده اللينك متكتب كامل بـ `https://` — من غيرها المعاينة مش بتظهر.

باقي الرسالة قصيرة عن قصد. في حقول اختيارية فاضية (`shipping`، `warranty`، `returns`،
`workingHours`) — لو عبّيت أي واحد فيهم بيظهر سطره في الرسالة تلقائياً، ولو فضّيته
يختفي. وأي حقل تخليه array بيتعرض كنقاط تحته:

```json
"shipping": ["عمّان والمناطق الكبرى: 1-2 يوم عمل", "باقي المحافظات: 2-4 أيام عمل"]
```

ترتيب السطور وصيغتها في [`src/message.js`](src/message.js).

### 2. المفاتيح

```bash
npm install
cp .env.example .env   # واملأ القيم من لوحة تحكم Meta
```

المفاتيح المطلوبة موضّحة بالتفصيل جوه [`.env.example`](.env.example):
`META_VERIFY_TOKEN`، `META_APP_SECRET`، `WHATSAPP_PHONE_NUMBER_ID`،
`WHATSAPP_TOKEN`، `FB_PAGE_TOKEN`.

### 3. التشغيل والربط

```bash
npm start
```

السيرفر لازم يبقى على رابط HTTPS عام عشان Meta توصله. للتجربة المحلية استخدم
`ngrok http 3000`، وللتشغيل الدائم أي استضافة (Railway / Render / VPS).

بعدها في [developers.facebook.com](https://developers.facebook.com) → التطبيق →
Webhooks، ضيف الرابط `https://your-domain.com/webhook` مع نفس `META_VERIFY_TOKEN`،
واشترك في الحقول دي:

| المنتج | الحقل |
| --- | --- |
| WhatsApp | `messages` |
| Messenger | `messages` |
| Instagram | `messages` |

## التأكد إن كل حاجة شغالة

```bash
curl localhost:3000/preview   # شكل الرسالة قبل ما تتبعت لحد
curl localhost:3000/health    # حالة السيرفر + عدد العملاء اللي اتبعتلهم
npm test
```

`npm test` بيشغّل كمان اختبار end-to-end بيقوم بالسيرفر الحقيقي قدام Graph API
وهمي، وبيبعتله نفس الـ payloads اللي Meta بتبعتها، وبيتأكد إن:

- Meta بتعرف تفعّل الـ webhook، والتوكن الغلط بيترفض
- الـ webhook المزوّر (توقيع غلط) بيترفض بـ 401 ومبيوصلش للطابور
- رسالة واتساب بترد بعد التأخير — **مرة واحدة بس** حتى لو العميل بعت 3 مرات
- ماسنجر وانستجرام بيردوا على Send API بالتوكن الصح
- إشعارات القراءة وردودنا الراجعة (echo) بتتجاهل

## الإعدادات

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `WELCOME_DELAY_SECONDS` | `60` | التأخير قبل الرد |
| `RE_WELCOME_AFTER_DAYS` | `0` | `0` = مرة واحدة مدى الحياة |
| `MAX_LATE_SECONDS` | `600` | يلغي الرسالة لو اتأخرت أكتر من كده |

## ملاحظات

- **نافذة الـ 24 ساعة في واتساب:** الرد المجاني مسموح خلال 24 ساعة من رسالة العميل،
  والدقيقة الواحدة جوه النافذة دي بمسافة كبيرة.
- **الكفالة مش مذكورة في سياسات الموقع.** لو قررت تضيف سطر `warranty` للرسالة، ضيفها
  كمان لسياسات Shopify — دلوقتي مفيش ذكر لكفالة السنة في أي سياسة عندك.
- **بيانات العملاء** بتتخزن في `data/contacts.json` (خارج git). لو مسحته، العملاء
  القدام هيستلموا الرسالة تاني.
- **سيرفر واحد بس:** التخزين ملف على القرص، فلو شغّلت أكتر من نسخة في نفس الوقت
  محتاج تحوّله لقاعدة بيانات.
